# 02 · 核心技术亮点

> 每个亮点按「是什么 → 难在哪 → 怎么解决 → 代码证据」展开。
> 面试时建议挑 2-3 个讲透，而不是 8 个都点到。

## 1. 一致点驱动的 Agent 循环收束与打断安全

**是什么**：Agent 主循环（`run_turn`）在 while 循环内依次检查：打断一致点 → 输出预算（262,144 token）→ 迭代上限（128 次）→ 收束提醒（nudge）→ auto-compact 阈值。

**难在哪**：Agent 循环的每个环节都可能被中断——用户打断、预算耗尽、迭代超限。如果在任意位置粗暴抛异常，历史消息里可能留下**没有 tool_result 的悬空 tool_use**，下一轮请求直接被 API 拒绝。

**怎么解决**：
- 所有检查点都刻意落在「用户消息/工具结果已落定」的一致点位置，此刻抛出不留悬空 tool_use；
- 预算耗尽不是静默截断，而是把收束原因作为 user 消息写进历史——模型看得见「该收了」，下一轮不会莫名其妙重新排查；
- 软 nudge 每回合至多一次（软收束比硬掐便宜），流内打断的零内容特殊情况在 `build_assistant_message` 校验前先算好打断标记。

**证据**：`aulos/runtime.py:1863-1930`（run_turn 循环检查点）、`runtime.py:755-805`（运行时旋钮：思考降档/委派预算/收束提醒）。

**面试话术**：这不是 try/except 补丁，而是**把 Agent 循环当成并发协议来设计**——先定义「哪些状态是合法的」不变量，再让所有路径都只在不变量成立的地方离开循环。

## 2. 同步内核 × 异步前端的零侵入桥接

**是什么**：Web 后端需要在 WebSocket 上实时推送 Agent 的每一步（流式文本、工具调用、权限请求），但内核 `run_turn` 是同步阻塞代码。

**难在哪**：两条路：把内核重写成 async（侵入性大，CLI 宿主也要跟着改），或让同步内核把事件「漏」给异步层（要解决跨线程通信 + 事件从哪来）。

**怎么解决**：选择后者——**三个代理对象在事件发生处镜像**，内核零改动：
- 事件循环线程管 WS 收发，工作线程跑同步阻塞的 `run_turn`；
- `emit()` 用 `loop.call_soon_threadsafe` 塞 asyncio.Queue，sender 协程专职消费；
- 权限审批回传走 `queue.Queue`（decide 阻塞等待用户点按钮）；
- `_LiveClientProxy` 包住模型客户端逐事件镜像 SSE、`EmittingToolRegistry` 镜像工具开始/结束、`WebPermissionPrompter` 镜像审批请求。

**证据**：`aulos/server.py:2-20`（头注释即线程模型设计文档）。

**面试话术**：内核在 CLI 和 Web 两种宿主下**零分叉**——GUI 需要的所有事件都通过代理镜像获得，而不是让内核知道「自己在被观测」。

## 3. 三层上下文压缩 + 摘要漂移对冲

**是什么**：长对话必然逼近模型窗口上限。Aulos 用三层递进压缩：
1. **MicroCompact**：纯字符串占位替换旧工具输出，零 LLM 成本；
2. **Session Memory**：后台线程滚动摘要（单飞行防并发、失败指针不动下轮重试）；
3. **Full Compact**：LLM 整段结构化压缩，与滚动摘要的重叠区复用，零额外调用。

**难在哪**：
- LLM 摘要是**有损的**，且多代接力误差单调累积——压缩再压缩，几代之后早期细节面目全非；
- LLM 服务本身会失败，压缩链路不能成为新的单点故障；
- token 估算直接影响触发时机：`len//4` 对中文低估 3~4 倍（触发线滞后数万 token，等发现已经爆了）；全局 `//2` 又对英文高估 2 倍。

**怎么解决**：
- **机械锚点**：归档区锚点由代码从原文机械抽取、永不经过模型改写，作为「摘要出错时的忠实底座」；
- **熔断降级**：LLM 摘要连续失败达阈值，自动降级为规则摘要——压缩链路永远不会因为模型不可用而断供；
- **CJK 分桶估算**：按中英文字符分桶分别估算，而不是一个全局除数。

**证据**：`aulos/compact.py`（三层实现 + `compact.py:14-34` token 估算）、README「长对话不爆上下文」节。

## 4. Windows 原子写问题域（fsatomic）

**是什么**：会话 JSONL、配置、记忆全部经由一个统一的原子写模块落盘。

**难在哪**：Windows 上「写临时文件再 `os.replace`」这个标准做法有三个真实故障模式（模块头注释原文记录）：
1. CPython 打开文件不带 `FILE_SHARE_DELETE` → 读者握着目标文件时 `os.replace` 抛 PermissionError；
2. 杀毒软件扫描临时文件造成瞬时锁；
3. **固定名临时文件多线程同写互踩**——线程 A 的 replace 把线程 B 的半截内容发布了，读者撞见非法 JSON，「数据看起来凭空消失」。

**怎么解决**：同目录**唯一**临时名（保持同卷 replace 的原子性）+ 指数退避重试（累计约 1.5 秒，覆盖杀软扫描窗口）。

**证据**：`aulos/fsatomic.py:1-19`（三个故障模式的文档化）、`tests/test_fsatomic.py`。

**面试话术**：这是「我踩过这个坑」级别的素材——尤其第三个，症状是「数据凭空消失」，根因是并发写共享临时文件名，排查过程本身就是好故事。

## 5. 防死循环/防套娃的多层护栏

**是什么**：Agent 是非确定性程序，会陷入重复行为或无限委派。Aulos 的护栏：

| 护栏 | 机制 |
|---|---|
| 委派预算 | 每回合一份委派额度，子 Agent 白名单内不能再派生——防无限套娃 |
| 重读去重 | 同一文件重复读取指纹去重，指纹经 **contextvar** 在并行批次间传递 |
| 只读重复拒止 | 同一只读操作第 3 次直接拒绝 |
| 输出瘦身 | 超长工具输出只留开头，全文落盘按需取 |
| 思考降档 | 回合内 thinking 自动降档（`with_thinking_downshift`） |

**难在哪**：contextvar 的跨线程语义——指纹必须在 turn 线程上 set，因为并行批次由 `copy_context()` 快照携带，**在创建线程上 set 池线程看不见**。这是 contextvars 文档不会主动告诉你的坑。

**证据**：`aulos/runtime.py:1871-1876`（contextvar 设置时机注释）。

## 6. 多 Agent 并行编排 + 执行层模型分层

**是什么**：Leader Agent 把可并行的子任务派生给 subagent 同时执行，全部完成后汇总。

**关键设计**：
- **白名单防套娃**：子 Agent 的工具白名单里没有「再派生」，从机制上杜绝无限递归；
- **幽灵任务清理**：进程重启后，遗留的「运行中」子 Agent 统一标记为失败——状态不会说谎；
- **执行层模型分层**：子 Agent 可配置便宜模型（workerProvider），Leader 保持强模型——决策质量不牺牲，执行成本大幅下降。

**证据**：`aulos/multi_agent.py`、`aulos/agent_tools.py`。

## 7. 三级权限 + 敏感路径强制确认

**是什么**：Agent 能跑真命令、改真文件，权限模型必须分层：
- **plan**（只读）→ **workspace-write**（工作区可写）→ **danger-full-access**（全放权）；
- 超出当前模式的操作弹人工审批；
- `.git/`、`~/.ssh/` 等敏感路径在**任何模式下都强制人工确认**——即使 danger-full-access 也不放行。

**设计洞察**：防的是「模型自我放权」——权限体系的威胁模型不仅是用户误操作，还包括模型自己在多步推理中「好心」升级权限。

**证据**：`aulos/permissions.py`。

## 8. Agent 级评测框架（evals）

**是什么**：单元测试之外的一层行为级保障——6 类能力任务（修测试/实现函数/跨文件重命名/代码审查/派子代理等），产出可对比的回归基线。

**关键设计决策**：
- **被测对象是 subprocess**：走真实入口 `main.py -p` 跑任务，评测框架不 import 被测代码——「测的是用户实际拿到的东西」；
- **双重判分**：确定性 checks（pytest 过没过、文件存在性）**且** LLM judge，任一不过即失败；
- **防作弊检查**：`file_unchanged` 检查防止 Agent「改测试凑绿」「删文件消音」；
- **基线回归**：结果存 `baseline.json` 随仓库走，退出码可直接当 CI 门槛；
- **零成本自测**：`--agent-cmd` 可替换成桩 Agent，评测管线自身用假 Agent 冒烟，不烧 token。

**证据**：`evals/README.md`、`evals/harness.py`、`evals/baseline.json`、`tests/test_evals_harness.py`。

**面试话术**：传统测试测「函数输出对不对」，evals 测「Agent 行为对不对」——这是测试非确定性系统的一次完整实践。
