# 03 · 问题解决案例

> 每个案例按 STAR 结构整理：**问题 → 根因 → 排查过程 → 解决 → 启示**。
> 排查过程是面试官最关注的部分——重点讲「怎么定位的」，而不是「改了哪行」。
> 所有案例在仓库中都有对应测试/文档证据。

## 案例 A：spawn 事件顺序依赖失败（测试串扰「两层雷」）

**问题**：全量回归中，subagent 的 spawn 用例只在「整个 test_agent_tools.py 先跑」时挂；单独跑、反序跑、分批跑都过。现象是 `subagent_started` 事件到了，但 worker 线程镜像的 `subagent_event`/`subagent_done` 一个都没到。

**根因（两层定性）**：
- 第一层：某个测试手工注入 3 元组全局工厂且手工还原，污染后续解包 4 元组的用例（已用 `monkeypatch.setattr` + 自动恢复修掉）；
- 第二层（主根因）：pytest 进程内累积的**跨线程状态泄漏**——dispatch 的 contextvar 绑定残留 + `import aulos.server` 的模块级副作用（全局 event bridge 设了没清理）+ 长时间运行中起过的真实后台 worker 线程，三者交互。

**排查过程（方法论亮点）**：
1. `git stash` 对照坏基线提交，排除本次改动引入 → 定性为「预先存在的雷」；
2. 干净独立进程手工模拟同链路，事件齐飞 → **代码路径正确，雷在 pytest 运行时状态**；
3. 二分定位：前 27 用例+spawn 过、后 26 用例+spawn 过、只有整文件先跑才挂；3 分钟 vs 3.5 秒的耗时差锁定了「起过真实后台线程的用例」；
4. 把「已排查过的事实」和「建议路径」写成跨会话交接文档（`docs/bug-spawn-emits-order-dependent.md`），避免重复走弯路。

**解决**：验收标准明确——正序/反序/全文件/全量全绿；修复允许落在测试侧（fixture 隔离）或产品侧（bridge/contextvar 清理接口），二选一要给理由；**禁止用 skip/xfail/删断言糊弄**；第一层的正确修复明确标注「勿回退」。

**启示**：全局可变状态（contextvar、模块级 bridge、单例）必须有测试清理契约；「单独跑必过、全量跑必挂」≠ 测试写错，要查进程内累积状态。教训已沉淀进 `AGENTS.md`。

**证据**：`docs/bug-spawn-emits-order-dependent.md`。

## 案例 B：子代理 12 分钟工作成果全丢（空消息三层防御）

**问题**：general 子代理连续工作 12 分钟，最终 assistant 消息只含 thinking 或纯 tool_use，`build_assistant_message` 收到空事件列表抛异常，worker 的 except 把整个任务打成 failed——**4 个脚本文件的产出全部丢失**。

**根因**：模型兼容层把 thinking delta 吞掉（流处理缺陷）+ build 逻辑对「空 blocks」零容错。两个因素叠加。

**解决（三层防御）**：
- L1 续写兜底：注入总结指令、关工具再跑一轮（最多 1 次）；
- L2 部分结果：兜底也失败时，从会话历史提取产物清单回传 COMPLETED——产出不再丢失；
- L3 降级：空 blocks 时用 thinking 文本转 text 块。

事故现场固化为最小复现测试（带日期的回归钉）。

**启示**：长任务 Agent 不能让「最后一帧为空」摧毁全部产出；对外部模型兼容层的行为不能信任，必须有降级链路；事故要留最小复现。

**证据**：`tests/test_agent_empty_final.py`（docstring 即事故报告）。

## 案例 C：并行 edit_file 竞态静默吞掉编辑

**问题**：`run_turn` 用 ThreadPoolExecutor 并行执行同一 assistant 消息里的多个 tool_use。两个 edit_file 指向同一文件时，「检查→读盘→内存替换→整文件重写」无锁执行——实测：一处编辑加上了，另一处**被静默吞掉，无任何报错**。

**根因**：两线程以同一磁盘版本为基线（read-modify-write 竞态），后写者整文件覆盖先写者。

**排查/解决（竞态 bug 标准打法）**：
1. 给 `_disk_text` 注入 50ms 延迟，**人为放大读-改-写窗口，让竞态确定性复现**（而不是靠运气撞）；
2. 按路径加锁串行化临界区：锁内刷新 FileStateCache，后到者以先到者落盘的新内容为基线；
3. 不同文件仍保持并行；
4. **双面回归**：新行为（并发编辑不丢）+ 旧行为不回归（串行路径结果不变）。

**启示**：竞态 bug 的标准打法是「人为放大窗口 → 确定性复现 → 加锁 → 双面回归」；「静默吞数据」类 bug 必须由事故驱动补测试。

**证据**：`tests/test_edit_race.py`。

## 案例 D：工具卡永远「运行中」（tool_use/tool_result 配对断裂）

**问题**：前端工具卡片永远显示「运行中」，不结束。

**排查**：怀疑镜像事件配对断裂。做法是**驱动真实链路**——worker 线程 + SSE 镜像代理 + 工具注册表 + 并行工具池，从 WebSocket 收全量事件，断言：每个 tool_use id 都有同 id 的 tool_result 到达，且**两个并发会话的事件互不串线**。

**解决**：修复落在 runtime 层「守卫→回调」一步，用 runtime 单测钉死。docstring 注明：「端到端是复现手段，守卫这一步才是修复本体」。

**启示**：分布式事件配对问题要「全链路复现定位 + 最小层测试固化修复」；并发会话事件串线要作为断言的一部分。

**证据**：`tests/test_tool_event_pairing.py`。

## 案例 E：「显示 A 调用 B」——模型选择的三连回归

**问题**：前端显示会话用模型 A，实际请求发的是模型 B；且「创建会话→首条消息」的空窗期内全局切模型会波及新会话。

**根因链（三个契约缺口）**：
1. 会话「跟随全局」只是回显，未固化落盘；
2. 固化后不广播 `model_changed` 事件，前端仍显示旧值；
3. 新会话创建瞬间不固化，留有空窗。

**解决**：pin 时必须落盘并广播；新建会话创建瞬间即固化全局 active（消灭空窗）；全局 active 无效时不落垃圾记录、维持跟随语义；用户显式选过的模型不被全局覆盖。**每个缺口单独钉一个回归**。

**启示**：一个用户可见 bug 背后往往是「状态源、持久化、广播」三处契约缺口；状态语义（固化 vs 跟随 vs 无效回退）要成套设计。

**证据**：`tests/test_session_settings_isolation.py`（注释带日期的回归钉）。

## 案例 F：并行工具炸 "cannot enter context: already entered"

**问题**：并行任务共享同一份 contextvars 快照，并发 `ctx.run` 直接抛异常，Web 端整个 turn 报错。

**解决/验证**：并行任务必须各自 `copy_context()`。测试用 `threading.Barrier` 对齐两个工具——**只有真能同时进入执行才算通过**（第二个工具进不来就超时炸穿），防止「假并行」测试绿。

**启示**：并发修复的测试要用栅栏强制真并发，否则测了个寂寞。与案例 A 是同一机制的一体两面：既要 copy 快照，又要防跨用例绑定残留。

**证据**：`tests/test_runtime.py:282`。

## 案例 G：PyInstaller 双执行自举崩溃 + AppImage 环境污染

**问题 ①**：v5.1.0 打包版启动即崩。`server.py` 以 `__main__` 执行时，功能域模块回投 `import server` 会把本文件**再执行一遍**——两份模块副本状态分裂。

**解决 ①**：先把真模块副本初始化出来，入口副本只当跳板（防双执行自举）。

**问题 ②**：Ubuntu 24.04 实测工具子进程 gst 崩溃、音频管线假死。onefile bootloader 把 `_MEIxxx` 临时目录塞回 `LD_LIBRARY_PATH`，污染子进程库解析。

**解决 ②**：导入期即清洗 AppImage 注入的环境变量。

**启示**：打包不是「能跑就行」——入口自举、环境变量继承这些「运行环境本身的坑」要专门设防。

**证据**：`aulos/server.py:40-58`、`PACKAGING.md`。

## 案例 H：三平台发布的平台坑与自动降级

**问题**：同一份代码在三个桌面平台的故障模式完全不同：
- Wayland 协议不允许客户端置顶/挪窗；
- VMware 无 3D 加速 → WebView 白屏；
- Linux 缺 GStreamer 插件 → 网页音频无声。

**解决（统一模式：探测 → 降级 → 可观测 → 逃生口）**：
- 检测 Wayland+XWayland 自动 `GDK_BACKEND=x11`，决策记录进 `boot.log`，保留 `AULOS_GDK_BACKEND` 环境变量逃生口；
- 检测到无 3D 加速自动 `WEBKIT_DISABLE_DMABUF_RENDERER=1` 回退非加速渲染；
- AppImage 形态播放前**主动探测**音频管线，不可用自动停用、只弹提示不卡死；
- 另有静默失败模式记录：签名密钥缺失时「构建成功但无 .sig」，不能作为更新目标；`latest.json` 断链会导致自动更新静默失效。

**启示**：跨平台发布的一半工作量在「环境探测 + 自动降级 + 可观测（boot.log）+ 逃生变量」；发版链路要专门记录静默失败模式。

**证据**：`docs/desktop-release-notes.md`。

## 案例 I：项目更名的数据保全设计（x-code → aulos）

**问题**：v5.0.0 完成更名，最大风险不是文案而是**标识符牵一发动全身**：`APP_NAME` 一改，`~/.aulos` 下全部会话/配置/记忆路径就「消失」；握手 token、ping 身份确认、装配标识都嵌着名字。

**解决（四板斧）**：
1. **双轨制**：显示名（Aulos）与技术标识符（`aulos`）分离，技术标识冻结并列表说明「为什么不能改」；
2. **单一事实来源**：产物文件名全部从 `tauri.conf.json` 的 `productName` 派生（脚本读配置），改名只动一处——否则 `latest.json` 指向不存在的文件，自动更新静默断链；
3. **无感迁移**：`LEGACY_APP_NAME` 保留一次性迁移逻辑（旧数据目录首启自动搬运）；
4. **生命周期声明**：遗留代码「新代码不引用、也不许删，直到宣布放弃旧版本升级」。

**启示**：改名/迁移类需求的正确姿势是「机制盘点表 + 单一事实来源 + 老用户无感迁移 + 遗留代码的生命周期声明」。

**证据**：`docs/naming-history.md`。

## 案例 J：两大巨石文件的渐进拆分

**问题**：后端 `server.py`（2800+ 行）与前端 `app.js`（近 7000 行、原生 JS 无模块系统）两个历史巨石，牵一发动全身。

**方案（不做大爆炸重写）**：
- **门面保兼容**：后端按低耦合域拆成多个模块，`import server` 的全部调用点与测试**零改动**（server.py re-export，共享可变态一律 call-time 解析保住 monkeypatch 语义）；随后全量包化进 `aulos/`；
- **先织网再动刀**：拆分前先建回归网——jsdom 断言真实源码 + 真实 index.html 骨架，Playwright 主干场景（流式回执/插队广播/断线重连）；
- **前端按依赖序外迁**：拆成 13 个按依赖序 defer 加载的域文件（-68%），定义「加载序契约」；
- **对过度重构说不**：app.js 剩余部分定性为「网状耦合核心，再拆需事件总线重构——待测试更厚时再评估」，并明确拒绝 ES 模块化（收益不再显著）。

**启示**：重构三板斧——门面保兼容（测试零改动是硬指标）、先织网再动刀、对「不再划算的进一步重构」显式说不了。

**证据**：`docs/refactoring-roadmap.md`。

## 方法论总结：事故处理闭环

以上案例共同构成一套完整闭环，也是面试收尾时可以主动总结的：

```
事故发生
  → 根因定性（排除本次改动 / 干净进程对照 / 二分定位）
  → 最小复现测试（人为放大竞态窗口 / Barrier 强制真并发 / 全链路驱动）
  → 分层修复（防御链 L1→L2→L3，而不是单点补丁）
  → 双面回归钉（新行为 + 旧行为不回归，带日期可追溯）
  → 陷阱文档化（AGENTS.md 已知陷阱 / docs/ 复盘文档）
  → evals 基线防复发（行为级回归）
```

一句话：**每个真 bug 留一个回归钉，每个事故沉淀一篇文档，每个坑变成一条测试纪律。**
