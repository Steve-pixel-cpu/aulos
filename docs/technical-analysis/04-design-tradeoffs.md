# 04 · 设计决策与权衡

> 「为什么选 X 而不是 Y」比「你用了 X」更有分析价值。
> 本文档整理项目的关键权衡决策，每项含：背景、选项、结论、代价与收益、证据。

## 1. 权衡决策表

### 1.1 Electron → Tauri（桌面壳迁移）

| | |
|---|---|
| **背景** | Electron 壳自带 Chromium，安装包 ~133MB，内存占用高 |
| **选项** | 保留 Electron vs 迁移 Tauri 2（Rust 壳 + 系统 WebView2） |
| **结论** | 全面迁 Tauri，Electron 弃用但**保留为可选打包目标**——迁移有回退路径 |
| **收益** | 安装包 133MB → 28MB（-79%）；原生通知/单实例/自动更新/多窗口能力 |
| **代价** | 牺牲了「自带 Chromium 的确定性」（不同系统 WebView 版本有差异）；需要 Rust 工具链 |
| **证据** | `electron/main.js:1` 弃用标注、`PACKAGING.md`、两壳进程模型逐条对齐（`src-tauri/src/main.rs` 头注释） |

### 1.2 同步内核 vs 重写为 async

| | |
|---|---|
| **背景** | Web 层需要异步推送事件，内核 `run_turn` 是同步阻塞代码 |
| **选项** | 内核重写为 async/io vs 同步内核 + 线程桥接 |
| **结论** | 不重写。事件循环线程 ↔ 工作线程 + 三个代理对象镜像事件 |
| **收益** | 内核在 CLI/Web 两种宿主下**零分叉**；重写的回归风险为零 |
| **代价** | 跨线程通信复杂度（call_soon_threadsafe、双队列），需要理解 contextvar 跨线程语义 |
| **证据** | `aulos/server.py:2-20` 头注释即设计文档 |

### 1.3 软收束 vs 硬截断（预算/迭代超限）

| | |
|---|---|
| **背景** | Agent 循环需要预算控制，超限时怎么停 |
| **结论** | 软 nudge（收束提醒写进历史）优先，硬掐兜底 |
| **理由** | 「提示落进历史后模型看得见『该收了』——比静默放行到 maxIterations 硬掐便宜得多」；硬截断模型不知道自己被掐，会重复排查 |
| **证据** | `aulos/runtime.py` nudge/budget 注释 |

### 1.4 压缩阈值：贴窗口 vs 留余量

| | |
|---|---|
| **结论** | 750k 触发线 = 1M 窗口的 75% |
| **理由** | 阈值若贴着窗口设，一次请求还要装 max_tokens=32768 的输出位，只会等 API 报 context length 而整轮炸掉——余量是给输出位留的 |
| **证据** | `aulos/runtime.py:44-50` |

### 1.5 turn 输出预算：262,144 是算出来的

| | |
|---|---|
| **结论** | 单回合输出预算 262,144 token |
| **理由** | 思考型模型一次大思考就能烧掉 1/4 预算；预算太紧会把轮次稳定掐死在「证据齐了」和「动手改」之间——这本身就是死循环排查的一环 |
| **证据** | `aulos/runtime.py:51-56` |

### 1.6 LLM 摘要 vs 规则摘要

| | |
|---|---|
| **结论** | LLM 摘要为主 + 机械锚点做底座 + 连续失败熔断降级为规则摘要 |
| **理由** | LLM 摘要质量高但会失败且漂移；锚点由代码从原文机械抽取、永不经过模型改写，是「摘要出错时的忠实底座」——压缩链路永不断供 |
| **证据** | `aulos/compact.py`、README 熔断降级节 |

### 1.7 evals 测真 Agent vs 桩 Agent

| | |
|---|---|
| **结论** | subprocess 拉真实入口测（可信但烧 token）+ `--agent-cmd` 桩补管线自测（零 token） |
| **理由** | 「测的是用户实际拿到的东西」要求真实入口；但评测框架自身的正确性不该烧钱验证 |
| **证据** | `evals/README.md`、`tests/test_evals_harness.py` |

### 1.8 测试隔离 vs 用户真实配置

| | |
|---|---|
| **背景** | 真实事故：泄漏的工作线程拿用户真实 API 额度打真网——「账户莫名 1302 限流、测试进程被 300s SSL 读拖住」；另有用户 MCP 配置混进共享工具集，导致「本地复现不了、只在配了 MCP 的机器上翻车」 |
| **结论** | conftest 三条 autouse fixture：关令牌门禁、掐断真实供应商连接、强制语言 + 隔离 settings |
| **理由** | 测试纪律：测试永远不碰用户的真实配置与真实额度 |
| **证据** | `tests/conftest.py:4-13`、`AGENTS.md` |

### 1.9 Prompt cache 友好排版

| | |
|---|---|
| **结论** | 不变部分（系统提示/工具定义）固定在前、变化对话在后 |
| **理由** | 命中供应商提示词缓存——省钱省时；但与压缩策略需协同设计（压缩会移动对话前缀，破坏缓存），两者要一起权衡 |
| **证据** | README「提示词排版」节 |

## 2. 迭代时间线

项目 32 个版本 tag 的演进弧线（据 git 历史 + tag 归纳）：

```
阶段 0 · 克隆与基建
  │  从开源项目 MiniCC 克隆，按 guides/ 13 篇指南顺序造轮子：
  │  api_client → 配置 → 会话存储 → runtime → main.py
  ▼
阶段 1 · 产品化雏形 (v1.2)
  │  WebUI 上线，工具面快速铺开（diff 展示、todo、统计、grep/glob、
  │  edit_file + FileStateCache），上下文压缩专项优化
  ▼
阶段 2 · 协议与流程
  │  OpenAI 协议支持（feature 分支 → dev → main）；
  │  形成 main/dev 双分支 + tag 发版节奏；浏览器工具、MCP
  ▼
阶段 3 · v4.x 打磨期
  │  视觉打磨（引入又移除亚克力效果）、MCP HTTP 修复、
  │  长回合延迟三件套 + 上下文瘦身四件套、
  │  执行层护栏（「把提示词约束下沉为执行层约束」）
  ▼
阶段 4 · v5.0 更名与桌面化
  │  x-code → aulos 更名（含 legacy 数据迁移）、
  │  Electron 弃用全面转 Tauri、三平台 CI 自动发版、
  │  「拆分 + 包化 + 厚测试」工程化还债（前端 -68%）
  ▼
v5.6.0 · 现状
   38k 行内核 / 1316 测试 / 6 类 evals / 三平台自动发版
```

**演进模式**：典型的「功能铺量 → 平台化 → 工程化还债」完整弧线——早期快速验证价值，中后期主动还技术债（测试、拆分、发版自动化），而不是等债爆雷。

## 3. 决策分析的三个视角

1. **没有免费选项**：每个决策都同时存在收益和代价（如 Tauri 省体积但放弃 Chromium 确定性）——只看收益的决策记录是没有分析价值的；
2. **决策有回退路径**：Electron 不删除而是保留为可选目标；遗留标识符有生命周期声明——可逆性本身是设计维度；
3. **参数是算出来的**：750k 阈值、262k 预算、1.5s 退避——每个数字背后都有具体推理，不是拍脑袋。
