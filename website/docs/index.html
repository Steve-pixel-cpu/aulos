GET STARTED

从第一个任务开始

连接你的模型，打开一个项目，把想完成的事情告诉 Aulos。

Aulos 是一个本地运行的开源编程 Agent。它可以阅读项目、修改文件、执行命令，并根据结果继续工作。你可以通过桌面应用、浏览器界面或终端使用它。

开始前，准备两样东西

一个支持工具调用的模型服务及其 API Key，以及一个你想了解或修改的本地项目文件夹。

1. 安装并打开 Aulos

从 GitHub Releases 下载适合系统和处理器架构的桌面安装包。Windows 用户还需要安装 Git for Windows，供 Agent 执行命令。

如果希望从源码启动，参阅源码运行。Python 环境要求只针对源码运行；使用打包好的桌面端无需自行安装 Python。

2. 连接一个模型

第一次打开时，在欢迎页填写 API Key、接口协议、Base URL 和默认模型，点击「保存并开始」。之后可以在「设置 → 模型」中修改或添加供应商。

这些字段应来自同一个模型服务。具体填写方式见连接模型。

3. 选择项目

新建会话，选择项目文件夹作为工作目录。先确认目录正确，再发送任务；Agent 会以这个目录为基础查找文件和执行命令。

试试这样开始

阅读这个项目，告诉我如何启动、测试入口在哪里，以及主要目录的作用。先完成说明。

4. 完成一次小修改

在了解项目后，给出一个范围明确的任务，说明期望结果和验证方式。例如：

一个可验证的任务

修复登录页邮箱为空时没有提示的问题。沿用现有表单样式，补上校验，并运行与登录表单有关的测试。完成后说明修改了哪些文件。

执行过程中查看工具调用、文件变更和命令结果；出现审批时核对具体操作。完成后在本地查看差异、运行项目，确认效果再提交。

INSTALLATION

安装与升级

下载桌面应用直接使用，或通过源码运行 Web 与终端界面。

安装桌面端

打开 最新 Release，展开 Assets，选择与你的系统及处理器架构匹配的安装包。以该版本实际提供的文件为准。

Windows
运行 setup.exe 安装包。安装 Git for Windows 后重启 Aulos，确保命令执行器可以找到 Git Bash。
macOS
打开 .dmg，将应用拖入「应用程序」。注意安装包的架构；首次启动若被系统阻止，可参阅macOS 首次打开。
Linux
按 Release 提供的格式安装。使用 AppImage 时需先赋予执行权限，再运行文件；系统还需要相应的 WebKitGTK 运行库。

完整桌面功能由 Tauri 版本提供，包括原生窗口、自动更新、电台与桌宠。

从源码运行

准备 Git 和 uv。项目要求 Python 3.14 或更新版本，uv 可按项目要求管理 Python 和依赖。Windows 还需要 Git Bash。

git clone https://github.com/Steve-pixel-cpu/aulos.git
cd aulos
uv sync

启动 Web 界面

uv run python server.py

在浏览器中访问 http://127.0.0.1:8000，通过欢迎页完成模型配置。服务的实际地址以终端输出为准。

启动终端界面

先按终端配置设置 API Key 和模型，再运行：

uv run python main.py

只有自行构建桌面安装包时，才需要额外准备 Rust 和 Node.js。开发者可阅读仓库中的 打包说明。

更新版本

桌面端有可用更新时，可按应用中的更新提示操作，也可从 Releases 下载新安装包。更新前完成正在执行的任务。

源码用户先查看工作区状态。工作区干净且当前分支跟踪官方 main 时，可以快进更新，再同步依赖：

git status
git pull --ff-only
uv sync

如果存在本地修改或分支分歧，先保存和处理这些修改。用户数据默认保存在 ~/.aulos/，与源码目录分开。

MODEL SETUP

连接模型

用你自己的模型服务，为主对话、子代理和后台任务选择合适的模型。

添加供应商

第一次启动使用欢迎页；后续进入「设置 → 模型」，点击「＋ 添加供应商」。填写连接信息，并为供应商添加可用的模型。

API Key
在模型服务商控制台生成的密钥，需要具备对应接口的调用权限。
接口协议
选择服务商支持的 Anthropic 或 OpenAI 兼容协议。协议要与所填端点匹配。
Base URL
填写服务商文档给出的 API 基础地址，通常包含所需的版本或产品路径。聊天网站首页不是 API 地址。
模型 ID
填写接口支持的确切模型标识。显示名称可以便于记忆，实际请求使用模型 ID。

模型需要支持工具调用，才能让 Agent 读写文件、执行命令。修改设置后，等保存状态完成，再从会话的模型菜单选择模型并发送一条简单请求。

套餐与 API 地址要对应

同一服务商的 Coding Plan 与普通 API 可能使用不同端点和额度。以所购服务的接入说明为准，不要混用地址与密钥。

在会话中切换

会话中的模型菜单会列出已启用供应商的模型。选中后，后续请求使用新的模型；此前对话仍属于当前会话。服务商的工具调用、图像输入和思考能力可能不同，切换时应确认任务需要的能力。

子代理与辅助模型

「设置 → 模型」中可以分别配置两类额外模型：

  • 子代理模型：用于被主 Agent 委派出去的任务，可选择适合执行工作的模型。
  • 辅助模型：用于自动起名、摘要等后台任务。

未单独配置时跟随主模型。配置前先在供应商列表中添加对应模型，避免选到没有权限调用的模型 ID。

上下文容量

根据当前接口实际支持的上下文窗口设置 contextWindow。第三方中转的限制可能低于模型官方标称值；设置过大可能在自动压缩前就被接口拒绝。

Aulos 会对长对话进行自动压缩。界面中的「上下文容量」可帮助观察使用情况；遇到超限时，先核对接口限制和配置，再重试。

配置和数据存放在哪里

Web 与桌面端通过界面保存供应商配置，默认存放在 ~/.aulos/settings.json。终端入口使用环境变量或 .env，详见终端配置。

会话和设置保存在本机。使用远程模型时，任务所需的提示词、代码片段和工具结果会发送给你配置的模型服务；联网工具和 MCP 也可能访问外部服务。

WORK WITH AULOS

把任务交给 Aulos

从明确目标到检查结果，让每一次修改都有可以核对的依据。

选择正确的项目

新建会话时选择工作目录。它决定文件搜索、读写和命令执行的位置，也影响项目级配置与 Skills 的发现。开始前看一眼当前目录，尤其是在多个项目之间切换时。

描述目标、范围与验证方式

一个好的任务描述通常包含：希望得到的结果、已有的相关文件或报错、需要遵守的约束，以及如何判断任务完成。

功能开发

给订单列表增加状态筛选。复用已有筛选组件，默认显示全部；切换状态后保留其他查询条件。完成后运行订单页相关测试。

定位问题

运行登录模块的测试，定位失败原因。先说明原因和修改范围，得到确认后再修改。

复杂任务可以先开启计划模式，让 Agent 阅读代码、整理方案，再批准执行。请参阅计划模式。

跟进执行过程

对话中会显示文件操作、命令执行和工具返回结果。遇到操作审批时，检查命令及目标路径，再选择批准或拒绝。需要调整方向时，可以打断当前任务并补充说明。

如果任务被分派给子代理，可以查看子代理的状态和返回结果。给互不依赖的模块分别安排任务，更容易核对每一部分的产出。

检查修改与测试

让 Aulos 总结修改的文件、关键行为变化和实际运行过的检查。随后查看代码差异，启动项目验证。可以在项目终端运行：

git status --short
git diff
git diff --cached

测试命令应使用项目已有的脚本。若检查没有运行或失败，继续处理这些结果，再决定是否提交修改。

继续历史会话

从侧栏打开历史会话即可继续讨论。任务跨度较大时，先补充当前目标和新的约束。终端可使用 -c 继续最近活跃的会话，或用 --resume 恢复指定会话。

会话记录默认位于 ~/.aulos/sessions/。长对话会自动压缩；长期有效的项目偏好可以存为记忆。

PERMISSIONS & CONFIGURATION

权限与配置

明确 Agent 可以操作的范围，并在需要时审批具体行动。

基础权限模式

workspace-write
允许工作目录和附加目录内的一般文件写入。只读探查命令可以直接执行；其他命令和范围外写入按规则请求审批。
prompt
工具操作通常会询问用户。已经匹配命令白名单的操作可直接执行。
danger-full-access
允许更广泛的文件操作和命令执行。显式拒绝规则与敏感路径保护仍然生效。

终端用 /mode 查看当前状态，使用 /mode workspace-write 等命令切换。allow 是终端支持的临时运行模式，不接受通过持久配置或免交互参数启用。

计划模式是独立开关

计划模式叠加在基础权限模式上，用于阅读、调研和制定方案。启用时按只读权限处理常规工具操作；关闭或批准计划后，回到原来的基础模式。

/mode
/mode plan

/mode plan 会切换计划开关，再执行一次可关闭。计划开关与命令白名单是不同机制，已有放行规则仍需单独管理。

操作审批与规则

审批面板会展示工具及其操作内容。终端通常可选择本次批准；命令支持时还可建立本会话或全局的放行规则。拒绝操作后，可以说明原因和希望采用的替代方式。

命中显式拒绝规则的命令会被拦截。对 .git/、Shell 配置和应用自身配置等敏感路径的写操作，以及检测到的敏感路径命令，需要单独批准；全访问模式也不会自动跳过这项检查。

配置文件与优先级

配置按以下顺序合并，后面的同名设置覆盖前面的设置：

  1. ~/.aulos/settings.json：用户级配置，跨项目生效。
  2. <项目>/.claude/settings.json：项目共享配置。
  3. <项目>/.claude/settings.local.json：个人在该项目中的本地配置。

部分环境变量还会覆盖文件配置。以下是一份项目级示例；上下文容量应按你的模型接口调整：

{
  "permissionMode": "workspace-write",
  "maxIterations": 128,
  "contextWindow": 128000
}

手动修改配置文件后重启服务，确保启动时读取的设置重新生效。包含 API Key 的个人配置应保存在本地。

控制任务长度

maxIterations 限制单轮工具循环次数，contextWindow 决定上下文容量，turnTokenBudget 可约束单轮 token 预算。这些限制帮助长任务及时收束，实际费用仍由模型服务商计费规则决定。

EXTEND YOUR WORKFLOW

扩展能力

通过 MCP 连接工具，用 Skills 保存工作方法，用记忆保留长期偏好。

MCP：连接外部工具

桌面端设置页提供 MCP 管理。也可以在任意一层配置文件中添加 mcpServers。支持 stdio、http 和 sse 三种传输方式。

下面使用本地文件系统 MCP 服务演示配置。需要先安装 Node.js，并将示例路径替换为实际目录；Windows 路径可写成 D:/projects/demo。

{
  "mcpServers": {
    "filesystem": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/absolute/path/to/project"
      ]
    }
  }
}

手动保存后重启服务。工具名称形如 mcp__filesystem__工具名，与内置工具一起参与权限审批。连不上时检查命令是否已安装、路径是否存在，以及服务的启动输出。

Skills：保存可复用的工作方法

一个技能是包含 SKILL.md 的目录。Aulos 支持用户级和项目级技能，同名时项目级优先：

~/.aulos/skills/review-checklist/SKILL.md
<项目>/.claude/skills/review-checklist/SKILL.md

下面是一份简单技能内容：

---
name: review-checklist
description: 审查代码改动并给出可复现的问题与验证建议。
---

1. 阅读当前 diff 和相关上下文。
2. 优先检查行为回归与边界条件。
3. 每个问题给出文件位置、触发条件和修复建议。
4. 总结已运行的检查和仍需验证的部分。

新建会话后，用终端 /skills 查看发现的技能，/skills review-checklist 预览内容。模型平时只接收技能简介，需要时再读取全文。

记忆：保留跨会话偏好

可以在对话中要求 Aulos 记住长期有效的信息，或通过终端管理：

/memory
/memory add 本项目文案统一使用简体中文
/memory rm 记忆ID前缀

记忆保存在 ~/.aulos/memory.json，后续会话可使用。定期清理过时约定，避免新任务继续采用旧信息。

多 Agent：分派独立任务

主 Agent 可以把调研或执行工作交给子代理，并汇总结果。适合任务边界清晰、彼此依赖较少的工作，例如分别定位两个模块的问题。

委派示例

请分别检查前端表单校验和后端接口校验，使用两个子代理进行只读调研，最后汇总不一致的地方和修复建议。

子代理可使用单独配置的模型，见子代理与辅助模型。任务是否能够执行，也取决于当前权限及子代理可用工具。

COMMAND LINE

终端使用

在终端中对话，恢复历史会话，或把单次任务接入脚本。

配置终端模型

先完成源码安装。在源码目录创建 .env，填写下面的变量。示例中的地址、密钥和模型均需替换为服务商提供的实际值。

API_KEY=your-api-key
ANTHROPIC_BASE_URL=https://api.example.com/anthropic
CLAUDE_MODEL=your-model-id
AULOS_PROTOCOL=anthropic

AULOS_PROTOCOL 默认是 anthropic，使用 OpenAI Chat Completions 兼容服务时设为 openai。当前终端实现仍通过 ANTHROPIC_BASE_URL 读取自定义地址，务必填写对应协议的基础端点。

终端入口需要 API_KEY。桌面端的欢迎页配置不会替代这一步；.env 中的真实密钥不要提交到仓库。

新建和恢复会话

# 新建会话
uv run python main.py

# 继续最近活跃的会话
uv run python main.py -c

# 列出历史会话，再用实际 ID 恢复
uv run python main.py --list
uv run python main.py --resume SESSION_ID

工作目录取自启动进程时的当前目录。如果要操作另一个项目，请在目标项目目录中通过源码和 Python 环境的绝对路径启动入口，并确保 API 环境变量已设置。

常用斜杠命令

/help
查看可用命令。
/status
查看当前会话和运行状态。
/model
查看模型；/model 模型ID 切换当前服务内的模型。
/mode
查看或切换权限；/mode plan 切换计划开关。
/thinking
查看当前思考等级和可选值，再按显示的值设置。
/compact
手动压缩当前对话上下文。
/rename
为当前会话设置名称。
/skills
查看已发现的技能。
/memory
查看和管理跨会话记忆。
/exit
退出终端会话。

免交互执行

使用 -p 传入一个完整任务，完成后退出。--output-format json 输出包含结果、会话 ID、用量和错误状态的 JSON，便于脚本处理。

uv run python main.py -p "阅读项目并说明测试入口" --output-format json

--model 和 --permission-mode 是 -p 模式下的覆盖参数。例如：

uv run python main.py -p "阅读 README 并总结启动步骤" --permission-mode plan --output-format json

无交互终端无法回答临时审批。自动化任务应预先设置适当的权限与命令规则；不要把需要审批时产生的失败当作任务已完成。

TROUBLESHOOTING

遇到问题时

从报错信息出发，先检查连接、配置和运行环境。

提示 API_KEY not set

这是终端入口缺少 API_KEY。检查启动环境或 .env，设置后重新运行。Web 与桌面端请使用「设置 → 模型」，它们的配置入口与终端不同。

401、403、404 或模型不可用

  • 401 / 403：检查密钥是否有效、账户是否有权限，以及套餐与 API 端点是否匹配。
  • 404：检查 Base URL、接口协议及版本路径，确认没有填写网页地址。
  • 模型不存在：核对模型 ID 的拼写和当前账户的可用模型。
  • 超时或连接失败：检查网络、代理和服务商状态；先用一条简单任务验证连接。

配置说明见添加供应商。

上下文超限或任务一直不能结束

先核对 contextWindow 是否超过当前端点实际支持的容量，特别是第三方中转服务。终端可用 /compact 手动压缩；必要时新建会话，并提供简短的任务总结和关键文件。

对于范围过大的任务，拆成可以分别验证的小步骤；达到迭代或 token 上限时，检查已经完成的工作，再继续剩余部分。

Windows 提示找不到 Git Bash

安装 Git for Windows 后，关闭并重新打开 Aulos 或终端。仅安装 Git 的编辑器插件不能替代 Git Bash。

macOS 首次打开被阻止

当前项目的打包说明注明 macOS 应用未做 Apple 公证。确认安装包来自项目官方 Releases 后，在 Finder 中右键应用并选择「打开」，或按系统「隐私与安全性」中的提示允许打开。

MCP 或技能没有出现

MCP：检查 JSON 格式、服务命令、参数路径和运行依赖；手动改配置后重启。Skills：检查目录中是否存在 SKILL.md、文件头部格式是否正确，并新建会话后用 /skills 查看。具体位置见扩展能力。

Linux 电台无声或桌宠异常

音频依赖 GStreamer；部分 AppImage 环境缺少兼容插件时，电台会停用。Wayland 的置顶与窗口移动限制也可能影响桌宠。可查看项目维护的 Linux 与桌面端排障说明。
